  I'm applying for the senior software developer role at Medrio. I've spent the last few years in insurance platform engineering and I'm ready for a problem that's different. I've been writing backend software for about 10 years, currently as a technical lead at AMA working on their Guidewire insurance platform and surrounding AWS infrastructure, and previously at Arterys building backend services for a medical imaging AI platform.

  On the C\# side: I've got Pleasant Solutions in my history (C\#/.NET, MVC, NUnit, Moq) and more recently I led a 2-3 engineer rewrite of a brittle legacy document generation system into ASP.NET Core microservices on .NET 8, deployed on Kubernetes with Helm and wired up to Datadog for observability. I also own 4 REST APIs at AMA serving 5 internal teams and external partners. My work has been in regulated environments, insurance with SOC 2 compliance, so supporting production systems under compliance and audit requirements isn't new territory.

  Quality and testing are genuine priorities for me. TDD is how I've worked for most of my career. Earlier at AMA I designed an automated test framework that cut defects by 30\% on subsequent projects; it got adopted across the insurance engineering team (~15 developers) and is still in use four years later. I set coding standards for a 12-person team, run code reviews, write PR checklists, and have delivered multiple projects with no critical defects post-launch.

  Two honest gaps worth naming: my SQL background is PostgreSQL, not SQL Server or T-SQL specifically, and my ORM experience is Guidewire's built-in data framework rather than EF Core or NHibernate. The concepts carry over and I ramp quickly on specifics. I'd be happy to talk more.
