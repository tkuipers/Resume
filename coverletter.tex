\begin{cvletter}
  I'm applying for the Senior Software Engineer role. The line about finding joy in making a product that customers love is what got me to read the rest, and the NaaS domain looks genuinely interesting. Building the backend and the APIs that sit underneath a product like that is exactly the kind of work I want to be doing.

  A quick note on the language, since you ask for Java or Kotlin. Most of my recent work is in Python and TypeScript, but I came up on the JVM. I wrote Java at Lockheed Martin early on, and I've spent several years since in Gosu, which is Guidewire's JVM language and is extremely close to Java: same type system, same OO model, same patterns, so moving back is a small step rather than a leap. OO design and the usual design patterns are how I think about structuring code regardless of what's on top.

  Most of what I do now is backend and API work. I own four REST APIs that internal teams and external partners build against, so I spend a lot of time on the things that make an API safe to depend on: clear contracts, versioning that doesn't break callers, and design standards I can point people to. I also led a small team rewriting a creaky legacy document system into containerized services on Kubernetes, which is the kind of "modernise the old thing without breaking the people using it" work your posting describes.

  On the leadership and quality side, I've been the technical lead on small projects, I write a lot of RFCs and design guides, and I do plenty of code review and pairing. Earlier on I built a test framework that cut defects by 30\% on later projects, and the team is still using it years later. I enjoy the mentoring part too, mostly helping newer developers get comfortable in code they find intimidating.

  I'll be honest that the networking side, IP routing and MPLS, is new to me. But ramping quickly on an unfamiliar domain is something I've done before and genuinely like doing. I'd be happy to talk more!
\end{cvletter}
